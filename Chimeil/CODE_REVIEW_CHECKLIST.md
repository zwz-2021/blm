# 代码评审清单

> 基于诊断报告 6.3 节要求建立，覆盖安全、事务、异常、测试、兼容、回滚六大维度。

## 1. 安全配置

- [ ] 无硬编码凭据（密码、密钥、token、证书路径）
- [ ] 敏感配置使用环境变量或密钥管理服务注入
- [ ] JWT 密钥强度足够（生产环境 ≥256 位随机值）
- [ ] 数据库/Redis/OSS 连接使用最小权限账号
- [ ] 接口权限校验完整（管理端/用户端分离）

## 2. 事务边界

- [ ] `@Transactional` 标注在多表写操作的方法上
- [ ] 事务传播行为合理（默认 REQUIRED，查询用 SUPPORTS 或 readOnly）
- [ ] 无长事务——避免在事务内调用远程服务或文件 IO
- [ ] 乐观锁/悲观锁策略正确（updateByIdAndStatus 等条件更新）
- [ ] 回滚异常类型覆盖 `RuntimeException` 及自定义业务异常

## 3. 异常处理

- [ ] 不捕获泛化 `Exception` 后吞掉（除非有明确理由）
- [ ] 不使用 `printStackTrace()` 或 `System.out`
- [ ] 业务异常继承统一基类，携带明确错误码和中文消息
- [ ] 全局异常处理器覆盖所有自定义业务异常
- [ ] 对外响应不泄露内部堆栈信息

## 4. 测试证明

- [ ] 核心 Service 方法有单元测试
- [ ] 测试覆盖正常路径、边界值、异常场景
- [ ] 修改已有逻辑时对应的测试用例同步更新
- [ ] 测试可独立运行，不依赖外部环境启动

## 5. 兼容性影响

- [ ] Controller 接口路径、参数、返回值未做不兼容变更
- [ ] DTO/VO 字段修改为向后兼容（新增字段放末尾或不影响序列化）
- [ ] 数据库脚本变更可重复执行（幂等 DDL）
- [ ] 第三方 API（微信支付、OSS）签名/回调格式无 breaking change

## 6. 回滚方式

- [ ] 变更可通过 Git revert 或功能开关恢复到上一个稳定版本
- [ ] 数据库变更已准备对应的回滚 DDL
- [ ] 配置变更已记录，可在部署前验证
